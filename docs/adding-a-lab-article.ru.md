# Как добавить новую статью в LAB

Эта инструкция пошагово описывает, как опубликовать новую статью в разделе
**LAB** (страница `/lab/<slug>`). Технических навыков не требуется — статья
это один Markdown-файл плюс несколько картинок.

Когда вы добавляете файл, остальное происходит автоматически:

- статья появляется по адресу `/lab/<ваш-slug>`,
- добавляется в выпадающее меню **LAB** в шапке,
- попадает в `sitemap.xml`,
- получает корректные SEO-теги (title, description, Open Graph, JSON-LD,
  хлебные крошки).

Есть два способа. Выберите один:

- **A. Админка Keystatic** (визуальный редактор, без ручного Markdown) — проще всего.
- **B. Markdown-файл** (создать/править файл напрямую или попросить LLM) — гибче.

---

## A. Через админку Keystatic (рекомендуется без навыков разработки)

1. Запустите сайт локально: `npm run dev`.
2. Откройте в браузере <http://localhost:4321/keystatic>.
3. Нажмите **LAB articles → + (Add)**.
4. Заполните поля (они один-в-один соответствуют «полям frontmatter» ниже).
   Картинки можно загрузить прямо в форме.
5. Нажмите **Save**. Keystatic создаст новый `.md`-файл в `src/content/lab/`
   и скопирует картинки в `public/images/lab/`.
6. Проверьте результат на `http://localhost:4321/lab/<slug>`.
7. **Опубликуйте** (см. «Публикация» внизу).

На этом всё — остальное можно не читать. Разделы ниже описывают те же поля на
случай, если вы предпочитаете править Markdown-файл вручную.

---

## B. Создание Markdown-файла вручную

### 1. Создайте файл

Добавьте новый файл в `src/content/lab/`. **Имя файла становится URL-адресом
(slug):**

```
src/content/lab/why-maps-matter.md   →   https://time2map.com/lab/why-maps-matter
```

Используйте короткое имя файла: латиницей, в нижнем регистре, через дефис, с
ключевыми словами (`barcelona-crime-map`, `offline-maps-guide`). Не
переименовывайте его потом — slug это публичный адрес страницы.

### 2. Добавьте frontmatter

Блок между двумя строками `---` в начале файла это **frontmatter** — настройки
статьи. Скопируйте шаблон и заполните:

```markdown
---
title: 'Barcelona Crime Map: Safety Index'        # заголовок H1 на странице
navLabel: Barcelona Crime Map                      # короткая подпись в меню LAB
seoTitle: 'Barcelona Crime by Neighborhood 2019–2025'  # заголовок вкладки + в Google
description: >-                                     # meta-описание (1–2 предложения)
  Crime analysis across Catalunya's 59 police zones: a composite safety index
  benchmarked against Spain's national average, with trends from 2019 to 2025.
publishDate: 2026-05-28                            # ГГГГ-ММ-ДД, для сортировки + SEO
displayDate: May 2026                              # дата в человекочитаемом виде
readTime: 8 min read                               # показывается рядом с датой
heroQuote: >-                                       # необязательная цитата под заголовком
  I built this map to make sense of public crime data...
mapEmbedUrl: https://catalunya-crimes.time2map.com/  # необязательный iframe (карта/приложение)
mapHints:                                          # необязательные подсказки под картой
  - icon: /images/icons/sidebar.svg
    text: Choose a crime type from the left panel.
  - icon: /images/icons/sliders.svg
    text: Drag the year slider to explore 2019–2025.
githubUrl: https://github.com/time2map/...          # необязательная кнопка "View source on GitHub"
ogImage: /images/lab/why-maps-matter/cover.png      # необязательная картинка для соцсетей
dataSources:                                        # необязательный список "Data sources"
  - label: Mossos d'Esquadra — ICGC viewer
    url: https://visors.icgc.cat/mapa-delinquencial/
authorBio: >-                                        # необязательная биография в карточке автора
  Geospatial developer based in Barcelona...
---
```

**Описание полей**

| Поле | Обязательное | Что делает |
| --- | --- | --- |
| `title` | да | Заголовок `<h1>` на странице. Сделайте его осмысленным и с ключевыми словами. |
| `navLabel` | да | Короткое название в меню LAB и в хлебных крошках. |
| `seoTitle` | нет | Заголовок во вкладке браузера и в выдаче Google. Если не задан — берётся `title`. Держите до ~60 символов. |
| `description` | да | Meta-описание (сниппет в Google + превью в соцсетях). 1–2 предложения, ~150–160 символов, с главными ключевыми словами. |
| `publishDate` | да | `ГГГГ-ММ-ДД`. Сортирует меню LAB (новые сверху) и питает SEO-теги и `<time>`. |
| `displayDate` | да | Произвольный текст даты на странице (например, `May 2026`). |
| `readTime` | да | Произвольный текст (например, `8 min read`). |
| `heroQuote` | нет | Короткая вводная цитата между строкой с датой и картой/текстом. |
| `mapEmbedUrl` | нет | Если задан — встраивается интерактивный iframe (живая карта или приложение) с кнопкой «Open full screen». |
| `mapHints` | нет | Список `{ icon, text }` — подсказки под картой. Иконки лежат в `/images/icons/`. |
| `githubUrl` | нет | Если задан — показывается кнопка «View source on GitHub». |
| `ogImage` | нет | Картинка для шеринга в соцсетях/мессенджерах. ~1200×630 px. Если не задана — берётся картинка сайта по умолчанию. |
| `dataSources` | нет | Список `{ label, url }` — раздел «Data sources». |
| `authorBio` | нет | Переопределяет биографию автора в карточке внизу. |

### 3. Напишите тело статьи (Markdown)

После закрывающего `---` пишите статью в Markdown. **Уровни заголовков
оформлены под конкретные роли** — используйте их по назначению:

| Markdown | Как выглядит | Для чего |
| --- | --- | --- |
| `## Раздел` | маленькая **терракотовая** подпись | названия разделов: `## Context`, `## Findings`, `## Methodology` |
| `### Заголовок` | большой заголовок **КАПСОМ** | главный заголовок раздела |
| `#### Заголовок находки` | заголовок 22px, **с авто-нумерацией** `01, 02, …` | каждый «пункт/находка» |
| обычный текст | чёрный текст | абзацы |

> **Важно:** никогда не вписывайте номера вручную. Каждый `####` внутри статьи
> нумеруется автоматически (`01`, `02`, …), а счётчик сбрасывается после каждого
> `##`. Просто пишите `#### Theft is actually declining` — номер `07` появится
> сам. Для подзаголовков, которые нумеровать **не** нужно, используйте `###`
> (а не `####`).

**Картинки и подписи.** Файлы картинок кладите в
`public/images/lab/<ваш-slug>/` и ссылайтесь на них абсолютным путём. Строка
*только из курсива* сразу после картинки становится её подписью:

```markdown
![Короткий осмысленный alt-текст для графика](/images/lab/why-maps-matter/chart.png)

*Подпись, которая показывается серым под картинкой.*
```

Всегда пишите осмысленный `alt` (в квадратных скобках `![...]`) — это важно для
доступности и SEO картинок.

**Ссылки, списки, цитаты** — обычный Markdown:

```markdown
Построено на [открытых данных]( https://example.com ) города.

> Важная мысль или примечание оформляется с терракотовой полосой слева.

1. Первый шаг
2. Второй шаг
```

### 4. Предпросмотр

Запустите `npm run dev` и откройте `http://localhost:4321/lab/<ваш-slug>`.
Проверьте размеры заголовков, авто-нумерацию находок, картинки и встроенную карту.

## SEO-чеклист (для каждой статьи)

- **`title` / `seoTitle`** — осмысленные, с главным ключевым словом; `seoTitle`
  до ~60 символов.
- **`description`** — 150–160 символов, читается естественно, содержит ключи.
- **Один `# H1`** — это поле `title`; никогда не добавляйте ещё один `#` в тексте.
- **Заголовки по порядку** — `##` для разделов, `###`/`####` ниже; не
  «прыгайте» через уровень ради оформления (роли выше уже дают нужный вид).
- **`alt` у картинок** — каждая картинка описывает, что на ней.
- **`ogImage`** — задайте картинку ~1200×630, чтобы ссылки красиво выглядели в шеринге.
- **`publishDate`** — корректная; питает `<time>`, сортировку и структурированные данные.
- **Внутренние ссылки** — где уместно, ссылайтесь на `/use-cases` или другие
  статьи `/lab/...`.

Фреймворк уже добавляет автоматически: canonical-URL, Open Graph / Twitter
карточки, JSON-LD `Article` + `BreadcrumbList`, элемент `<time>` и запись в
sitemap. Это трогать не нужно.

## Публикация

Сайт статический — изменения появляются после пересборки/передеплоя.

1. Убедитесь, что `npm run build` проходит без ошибок.
2. Закоммитьте новые файлы (`.md` и картинки):
   ```bash
   git add .
   git commit -m "Add LAB article: <название>"
   git push
   ```
3. Задеплойте (см. раздел про деплой в [README.md](../README.md)). Если настроен
   автодеплой — достаточно `git push`.

Вот и весь процесс — один Markdown-файл, несколько картинок и коммит.
